# Schema

Table `v_validators`. Model `ThreeLeaf\ValidationEngine\Models\Validator`.

| Column          | Type      | Notes                                                     |
| --------------- | --------- | --------------------------------------------------------- |
| `validator_id`  | UUID      | Primary key. Generated by `HasUuids`.                     |
| `name`          | string    | **Unique.** Used as an alternate lookup key.              |
| `description`   | string    | Nullable.                                                 |
| `context`       | string    | Nullable. Free-form grouping label.                       |
| `order_number`  | integer   | Default `0`. Added by a later migration, after `context`. |
| `active_status` | enum      | `Active` or `Inactive`. Default `Active`.                 |
| `created_at`    | timestamp | Database default `useCurrent()`.                          |
| `updated_at`    | timestamp | Database default `useCurrent()`, `useCurrentOnUpdate()`.  |

`active_status` is a database `enum` restricted to the two values of the
`ActiveStatus` PHP enum.

`order_number` is not part of the original table. Migration
`2025_06_23_093415_validator_add_order_number` adds it with a default of `0`.
Note that this is the ordering of **validators**, and is distinct from the
`order_number` on the [join table](validator-rules-table.md), which orders rules
inside one validator.

## Relations

```php
public function rules(): BelongsToMany
```

`belongsToMany(Rule::class, 'v_validator_rules', 'validator_id', 'rule_id')`.

The relation carries no `orderBy` and no `wherePivot`, so it returns every
linked rule in database order regardless of the join row's `order_number` or
`active_status`. [System Overview](/architecture/system-overview.md) records the
same point about the execution path.

## Fillable

`name`, `description`, `context`, `order_number`, `active_status`.

## Lookup by name

`ValidatorService::runValidatorById()` accepts a value that matches **either**
`validator_id` or `name`, and additionally requires `active_status` to be
`Active`. An inactive validator is therefore not found rather than found and
skipped.

# Examples

```php
use ThreeLeaf\ValidationEngine\Enums\ActiveStatus;
use ThreeLeaf\ValidationEngine\Models\Validator;

$validator = Validator::create([
    'name'          => 'StateAndTimeValidator',
    'description'   => 'Validates state and Monday business hours.',
    'active_status' => ActiveStatus::ACTIVE,
]);
```
